# Аномалии в review.csv

Файл заявлен как «свежая выгрузка для той же базы». Загружен скриптом [load_review.py](../../load_review.py) в отдельную таблицу `companies_review` — **намеренно не в `companies`**, потому что данные грязные и слить их с проверенным архивом означало бы молча испортить его.

Всего в файле 207 строк данных (208 с заголовком).

## Главное: это не выгрузка той же базы

| Показатель | Значение |
|---|---|
| Строк с непустым `id` | 205 |
| Из них уже есть в `companies` | **6** |
| Новых `id` | 199 |
| Расхождений в этих 6 записях | **0** — побайтово совпадают с архивом |

Если бы это была свежая выгрузка того же набора, пересечение было бы почти полным, а у существующих компаний обновились бы `rating`/`reviews_count`. Здесь наоборот: 97% строк — новые `id`, а те 6, что пересекаются, не изменились ни в одном поле. Похоже, это **другой набор данных**, а не обновление текущего.

**Как обнаружено:** сверила `id` из CSV с загруженным архивом и для пересечения сравнила все поля попарно — расхождений не нашлось.

## Порча данных

### 1. Сдвиг колонок — 1 строка

`c_001015`: `category='Пермь'` (это город), `city='ул. Советская, д. 89, офис 43'` (это адрес), `address=''` — значения съехали влево на одну колонку начиная с `category`, категория потеряна.

**Как обнаружено:** собрала списки допустимых городов и категорий из архива и проверила, все ли значения CSV в них попадают. Город «Пермь» оказался в колонке категорий.

### 2. Битая кодировка — 2 строки

`c_001008`, `c_001128`: `РњРѕСЃРєРІР°`, `РћРћРћ В«Р—Р°СЂСЏ РўРµС…В»`. Это UTF-8, прочитанный как CP1251.

**Как обнаружено:** те же проверки по словарю городов. Подтвердила обратным преобразованием — `'РњРѕСЃРєРІР°'.encode('cp1251').decode('utf-8')` даёт `'Москва'`, а испорченные названия — `'ООО «Заря Тех»'` и `'ООО «Темп Медиа»'`.

### 3. Разнобой в написании городов — 4 строки

| Значение | Проблема |
|---|---|
| `Moscow` | латиницей |
| `москва` | со строчной |
| `Москва ` | висячий пробел |
| `Санкат-Петербург` | опечатка |

Без нормализации это 4 отдельных «города» вместо двух существующих — любая группировка по городу поедет.

**Как обнаружено:** сверка со списком из 20 городов архива + отдельная проверка на `value != value.strip()`.

## Невалидные значения

### 4. `rating` — 24 строки с проблемами

| Значение | id | Проблема |
|---|---|---|
| `N/A` | `c_001083` | текст вместо пустоты |
| `4,5` | `c_001010` | десятичная запятая вместо точки |
| `-3` | `c_001122` | отрицательный |
| `7.2` | `c_001186` | больше максимума 5 |
| пусто | 20 строк | пропуск (сам по себе допустим) |

Из них 23 не приводятся к числу в формате базы (20 пустых, `N/A`, `4,5`, `-3`). Отдельно опасны `-3` и `7.2`: они формально числа и в `NUMERIC(2,1)` прошли бы молча, испортив средние рейтинги.

### 5. `reviews_count` — 5 строк не целое

| Значение | id | Проблема |
|---|---|---|
| `много` | `c_001187` | текст вместо числа |
| `45.5` | `c_001079` | дробное для счётчика |
| `-10` | `c_001116` | отрицательный |
| пусто | 2 строки | пропуск |

### 6. Телефоны и сайты

- `c_001004`: `8 (925) abc-12-34` — буквы вместо цифр
- `c_001091`: `+7` — обрезанный номер
- `c_001064`: `нет сайта` — текст в поле URL вместо пустого значения
- `c_001020`: `htp://sintez-service-453.ru` — опечатка в схеме

**Как обнаружено:** проверила `phone` регуляркой по формату архива `+7 (XXX) XXX-XX-XX`, а `site` — на префикс `http://`/`https://`.

## Структурные проблемы

### 7. Две полностью пустые строки

Строки 207 и 208 — все девять полей пустые. Похоже на «хвост» при выгрузке.

### 8. Дубликаты `id` внутри файла — 3 штуки

`c_001075`, `c_001049`, `c_001050` встречаются по два раза. Строки полностью идентичны, так что данные не теряются, но реальных записей 202, а не 205.

### 9. Подозрительный диапазон `id` — 6 строк

`c_900006`–`c_900011` выпадают из общей нумерации (`c_000001`–`c_001xxx`). У них же другой стиль названий — без кавычек-ёлочек: `АО Сокол` вместо `АО «Сокол»`, тогда как в архиве такой формат только у ИП. Похоже на вставку из третьего источника.

**Как обнаружено:** сгруппировала `id` по тысячным диапазонам — выделилась изолированная группа; посмотрев эти строки целиком, заметила и разницу в оформлении названий.

## Что сделано

Данные загружены как есть в `companies_review` (все колонки `TEXT`, без ограничений) — чтобы ничего не отвалилось при вставке и все битые значения были видны глазами. Колонка `csv_row` хранит номер строки в исходном файле, чтобы находить проблему в оригинале.

В `companies` файл **не сливался**. Прежде чем это делать, нужно решить как минимум: чинить ли кодировку и сдвиг колонок, нормализовать ли города, что делать со значениями вне диапазона и считать ли `c_900xxx` валидными.
